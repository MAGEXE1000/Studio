## Bugs Found
- **Developer Tools Shifting/Clipping**: When the Settings list was scrolled before opening Developer Options, the entire page shifted up by the scroll offset and became partially clipped and unscrollable at the top. (Status: **RESOLVED**)
- **Missing OS & Version Code Telemetry**: Native Android version info returned `N/A` or `-999` in the diagnostics telemetry view because the fields were not packaged or correctly mapped in the Capacitor plugin. (Status: **RESOLVED**)

---

## Root Causes Discovered
1. The scrollable container `scrollRef` in `StudioHub` was not positioned (`static`) on mobile subpages. Absolute-positioned sheets inside it shifted visually by `scrollRef.scrollTop` when scrolled.
2. Safe Area top padding `env(safe-area-inset-top)` was applied at both the parent `StudioHub` root level and independently inside the subview headers, creating a double offset.
3. Native PackageManager fields like `versionCode` and `osVersion` were absent in `AppInstallerPlugin.java`'s `getDeviceInfo()` return object.

---

## Solutions Implemented
1. Set `scrollRef` container to `position: 'relative'` and `overflowY: 'hidden'` when subpage sheets are active.
2. Removed `env(safe-area-inset-top)` from child headers, letting the parent `StudioHub` handle it.
3. Updated `AppInstallerPlugin.java` to fetch app metadata natively and populate `packageName`, `versionName`, `versionCode`, and `osVersion`.
4. Enhanced report generation logic to format sections and filter out all sentinel variables.
